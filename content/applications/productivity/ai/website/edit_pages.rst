======================
Edit pages with the AI
======================

Website designers who have the :guilabel:`Customize UI & schema` capability can ask the AI panel
(see :doc:`../panel`) to work on the website: create pages, change existing pages and the footer,
restyle blocks, edit the menu and apply brand kits. That capability is off by default and for
administrators only (see :doc:`../feature_access`). The AI bubble is in the top bar of the website
preview too, so you can open the panel while you look at the page. The same tools also work inside
the website editor (see :doc:`editor`).

The shipped agent :guilabel:`Website builder` is set up for this: it first reads the pages and
menus, proposes changes and never says that something is done before you confirm it.

Examples of requests:

- "On the About us page, make the first title shorter and change the button to point to the contact
  page."
- "Remove the third block of the homepage and move the FAQ to the end."
- "Give the pricing block a dark colour combination and more space above and below."
- "Add our phone number to the footer."

What the AI can change
======================

The AI reads a page (or the footer) as an outline: its blocks in order, and in each block the
headings, paragraphs, buttons, links, pictures, icons and repeated items such as cards or questions.
It then sends a list of operations, at most 50 at a time, applied together:

- change a text, or the address and label of a link or button;
- replace a picture and its alternative text, or the background picture of a block;
- remove, move or duplicate a block, or an item inside a block (a card, a question, a number);
- insert a new block from the catalogue;
- set the options of a block (see below) and give a block an anchor for ``#anchor`` links.

It can also create new unpublished pages, add a block to a page, add, rename and reorder menu
items, apply a brand kit and change the AI-managed custom CSS.

.. note::
   - The footer is edited like a page. The first AI change makes a copy of the footer for this
     website, as the website editor does when you edit it.
   - Pages generated by an application (the shop, the blog, event pages…) and the header are not
     edited by the AI: change them in the website editor.
   - Every operation names the element it changes. If the page was changed meanwhile, the operation
     is refused and the AI reads the page again, so it never overwrites a newer version by mistake.

Block options
=============

The AI styles blocks with the options the website editor itself offers, not with hand-written CSS:

- colour combination (one of the website's five, or none);
- space above and below the block;
- text alignment (start, centre, end);
- width (small, regular, full width) and height (automatic, half screen, full screen);
- background picture, or none;
- shadow and rounded corners of a block or an item.

The AI uses, in this order: texts, links and pictures; block options; a brand kit for colours and
fonts of the whole site; and custom CSS only when nothing else can do it.

Building blocks
===============

New pages and new blocks use the website's own building blocks. A catalogue of 32 blocks is
prepared for the AI with what each one is for: covers and banners, titles and text blocks, text with
picture, columns, features and cards, numbers, timelines, tabs, pricing tables, team members,
quotes, logos, picture galleries and mosaics, calls to action, FAQ, contact information and a
contact form. A theme's own version of a block is used when the theme has one.

When :guilabel:`Let the AI use all building blocks` is on (the default), the AI may also use every
other block of the website's block panel, theme blocks included; their texts and pictures are found
automatically. Blocks that show records, embed other sites, run scripts or send forms are never
offered. Turn the setting off to keep to the curated blocks (see :doc:`setup`).

.. note::
   The contact form sends its messages to the company's e-mail address. It never creates records
   of other applications.

Pictures
========

A new picture can come from:

- a stock photo of Unsplash, when an Unsplash key is set in the website settings;
- a picture generated by AI, when an image model is configured (see
  :doc:`../models_and_providers`);
- a public picture of the website's media, or a picture attached to the AI conversation;
- an address on the internet. The server downloads it with strict limits (public addresses only,
  10 MB, 10 seconds, picture files only) and stores it as a website picture; it is never linked
  from the other site.

Links and custom CSS
====================

- Links. The builder links only to pages and anchors that exist on this website, to its own
  absolute addresses, to e-mail addresses and to phone numbers. A made-up path or a link to another
  website is replaced and listed on the card; a menu item that points to another website is refused.
  An administrator can lift this with :guilabel:`AI may add links to other websites` (see
  :doc:`setup`). Such links are then still marked on the card.
- Custom CSS. The AI may only write plain CSS rules between its own markers in the website's custom
  stylesheet; your own rules outside the markers are kept. The CSS can apply to the whole site, to
  one page or to one block: for a page or a block, every rule is limited to it automatically, so it
  cannot change other pages. Sass is refused (variables, interpolation and the like), as are
  imports, scripts, functions that CSS does not know and at-rules other than ``@media``,
  ``@supports``, ``@keyframes`` and ``@font-face``. An ``url()`` may only point to pictures and
  static files of this site. The website's style bundle is compiled with the new rules before
  anything is saved; if it does not compile, nothing is saved and the error is shown.

Confirmation cards
==================

Website changes are public, so they are always proposed first: the panel shows a card that you
confirm or cancel (see :doc:`../panel`). Only the :guilabel:`Apply without asking` write mode
applies them straight away; the mixed mode still asks. The card shows the full content of the
change, not a summary: for page edits every operation with the text before and after, for new blocks
every block with its title, texts, buttons and their targets, the replaced links, a note when a
block goes onto an already published page and, for CSS changes, the complete CSS. A link to another
website is marked on the card with the host it leads to. The change is checked again when you
confirm.

Every applied change is recorded in the AI changes and can be undone (see :doc:`history`). When the
visual check is available, the AI can look at a screenshot of the page after a large change (see
:ref:`ai/website/visual-check`).

If a turn has no builder tools (the capability is missing or you are not a website designer), the
assistant tells you that the :guilabel:`Customize UI & schema` capability or the website designer
right is missing, that an administrator can grant it, and explains the manual way instead: Menu
Editor, Pages, edit mode and theme settings.
